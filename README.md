# CLAUDE MONET

Авторский адаптивный сайт французского ресторана: **Parisian Luxury × French Fine Dining × Cinematic Editorial**.

Неофициальный фанатский дизайн-концепт по мотивам сериала «Кухня» для портфолио веб-разработчика. Не связан с правообладателями. Не представляет настоящий ресторан. Бронирование демонстрационное.

## Стек

Vite · React · TypeScript · Tailwind CSS 4 · Motion · Lucide React.

Кремовый фон, глубокий бордовый, тёмный шоколад, приглушённое золото, Cormorant Garamond и Manrope. Шрифты собираются локально через Fontsource, без Google Fonts. Фотографии — фиксированные источники Unsplash с адаптивными размерами и локальной заглушкой.

## Запуск

Нужны Node.js **22.12+** и npm, а также доступ к npm registry при первой установке.

```bash
npm install
npm run dev
```

Открыть **http://localhost:5173/claude-monet/**. Если порт занят, Vite напечатает другой.

```bash
npm run typecheck
npm test
npm run build
npm run preview
```

Production preview: **http://localhost:4173/claude-monet/**. Готовые файлы — `dist/`.

При первой успешной установке npm создаст `package-lock.json`. Добавьте его в репозиторий; после этого для воспроизводимой установки используйте `npm ci` вместо `npm install`, в том числе в workflow. Lockfile не был сфабрикован при недоступном registry.

## Что реализовано

- Полноэкранный hero с приоритетной загрузкой фотографии, тонким параллаксом и навигацией.
- История с асимметричной композицией фотографий и авторским текстом.
- Шесть категорий меню, 18 вымышленных блюд и напитков, цены в тенге, порции, описания и аллергены.
- Клавиатурное переключение вкладок: `←`, `→`, `Home`, `End`.
- Окно блюда с составом и аллергенами.
- Три фирменных блюда с ручным переключением, без автоматической карусели.
- Асимметричная галерея и полноэкранный просмотр: `←`, `→`, `Esc`, кнопки предыдущего/следующего кадра.
- Мобильная навигация, нативные модальные окна с удержанием фокуса, возвратом фокуса и блокировкой фоновой прокрутки.
- Самостоятельный раздел об атмосфере.
- Форма демонстрационного бронирования с доступными ошибками и экраном подтверждения.
- Контакты и часы с пометкой «Демо», информация о проекте и обязательный дисклеймер.
- Семантическая разметка, skip-link, видимый фокус, reduced motion, lazy loading, srcset/sizes, резервные шрифты, обработка ошибок изображений и React ErrorBoundary.
- SEO description, Open Graph, favicon, русский язык документа. Намеренно отсутствуют LocalBusiness-разметка, реальные отзывы и вымышленный рейтинг действующего заведения.

Все кнопки и ссылки имеют действие. Ссылки навигации ведут в существующие разделы. Номер телефона и email демонстрационные, не являются ссылками для звонка или отправки письма.

## Бронирование и данные

Запросы на сервер **не отправляются**. Не используются база данных, localStorage, cookies и аналитика. Значения существуют только в React state и очищаются при повторном запуске сценария или обновлении страницы. Можно использовать вымышленные данные, например `Анна`, `+7 (700) 123-45-67`.

Проверки:

- имя: 2–60 символов, буквы Unicode, пробелы, дефисы и апострофы;
- телефон: 11 цифр с начальной `7` или `8`; допускаются `+`, пробелы, скобки и дефисы;
- существующая дата от сегодня до 90 дней вперёд;
- время 12:00–22:00 с шагом 30 минут; прошедшие слоты сегодня недоступны;
- 1–8 гостей;
- пожелания до 500 символов, необязательно.

Даты и время вычисляются в **локальном часовом поясе посетителя**. Валидация повторяется при отправке, поэтому изменение даты через DevTools или переход через полночь не обходят ограничения. Ошибки связаны с полями через `aria-describedby`; фокус переходит на первое ошибочное поле.

## Проверки

### Логика формы

```bash
npm test
```

Node.js test runner, без дополнительных пакетов. 11 тестов: успешная форма, пустые значения, реальность и границы дат, прошедшие слоты, Unicode-имена, телефон, число гостей, лимит пожеланий, полночь и конец дня.

### Браузерные проверки

```bash
npm run build
npx playwright install chromium
npm run test:e2e
```

На Linux при необходимости: `npx playwright install --with-deps chromium`.

Можно использовать уже установленный Chromium:

```bash
PLAYWRIGHT_EXECUTABLE_PATH=/path/to/chrome npm run test:e2e
```

Playwright запускает production preview с base path `/claude-monet/` и проверяет:

- desktop 1440 px и mobile 390 px;
- переключение категорий и диалог блюда;
- полный сценарий формы и отсутствие исходящих POST;
- мобильное меню, фокус, Escape и управление галереей;
- переключение фирменных блюд;
- отсутствие горизонтального переполнения на 320, 360, 390, 768, 1024, 1440 и 1920 px;
- автоматически выявляемые нарушения доступности через axe-core.

В автоматических UI-тестах запросы к Unsplash **намеренно прерываются**: проверяется настоящий механизм локальной заглушки, а тесты не зависят от доступности внешнего фотосервиса. Фотографии, их кадрирование и визуальное качество дополнительно проверяются вручную при обычном интернете. Автотесты не заменяют проверку со скринридером.

### Фактически выполнено в среде создания

- `npm install` выполнен, но завершился сетевой ошибкой `EAI_AGAIN` / `getaddrinfo registry.npmjs.org`.
- 11 тестов логики бронирования выполнены и прошли.
- Часть инструментов восстановлена из уже доступных локальных зависимостей. TypeScript-проверка выполнена, но **не прошла**: отсутствует модуль `motion/react`, который невозможно скачать в этой среде.
- `npm run build` выполнен, но **не прошёл** по той же причине. Production-артефакт не подтверждён.
- `npm run test:e2e` выполнен, но production preview не смог запуститься без сборки; полноценная проверка интерфейса **не завершена**. Адаптивность в реальном браузере пока не подтверждена.
- Фотографии не скачаны локально из-за сетевых ограничений; приложение использует фиксированный Unsplash CDN и локальную заглушку.

После восстановления сети выполните команды установки, проверки и сборки выше. Эти ограничения относятся к проверке в окружении, их нельзя считать успешным QA.

## GitHub Pages

В `vite.config.ts` задан корректный base:

```ts
base: '/claude-monet/'
```

Все локальные статические ресурсы используют `import.meta.env.BASE_URL` либо `%BASE_URL%`. Сайт одностраничный, навигация через якоря, серверный роутинг и fallback на `index.html` не нужны.

1. Создайте репозиторий **claude-monet** и загрузите проект в ветку `main`.
2. В **Settings → Pages → Build and deployment → Source** выберите **GitHub Actions**.
3. Workflow `.github/workflows/deploy.yml` установит зависимости, проверит TypeScript, тесты формы, production-сборку и браузерные сценарии, затем опубликует `dist`.
4. Адрес: `https://<ваш-логин>.github.io/claude-monet/`.

Workflow также запускается вручную через `workflow_dispatch`. Публикация из текущей среды не выполнялась. Репозиторий и аккаунт GitHub не создавались.

Если имя репозитория меняется, обновите `base` в `vite.config.ts` и `baseURL`/`webServer.url` в `playwright.config.ts`.
